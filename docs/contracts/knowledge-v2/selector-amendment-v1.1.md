# Category selectors and dynamic Compartments amendment v1.1
Engineering review candidate. This specification consolidates accepted driver/security design into the selector amendment. It does not represent implementation, deployment or human TST acceptance.

## 1. Versioned boundary and registry
The existing Service registry is the sole outer source registry. Endpoint/credential/network policy and subject mode remain owner-plane configuration; descriptors cannot redirect dials. Driver/connector inventories remain satellite-private. V1 remains unchanged: classes1..16, exact declared named Compartments1..64, kinds routing at core only, historic descriptor equality pinned into v1 handles. V2 explicitly advertises protocol_version2, compartment_mode dynamic-opaque, classes1..16 and category vocabulary1..64. Its capability predicate requires valid v2 descriptor plus owner-configured endpoint, rather than v1's static compartment list. It cannot be advertised as v1.

Opaque compartment IDs use stable randomly generated UUIDs with at least128 bits of entropy before UUID format/version bit application; cryptographic random UUIDv4 is accepted. IDs carry no principal/project/path meaning. Labels max128 are private authorized display data, not a global catalogue. No per-user descriptors/endpoints or expanded v1 limits. If authorized listing is introduced it is current-ACL scoped with100/page cap; no global total.

## 2. One normalization and four surfaces
REST query, MCP tool arguments, CLI flags and GUI selector controls resolve to selector-v2.schema.json#/$defs/query. CLI repeated values and GUI selected values become arrays; REST/MCP use arrays directly. q is unchanged. Omitted kinds expands to sorted code,data,docs; omitted categories remains absent. Deduplicate then sort every selector array lexically before hashing. Explicit empty arrays reject. Arrays OR internally; source/kind/category dimensions AND with authority. Intent is a ranking hint only and cannot replace hard categories.

Normalized source-facing filter is {version:2,kinds:[...],categories?:[...]}. Hash is SHA256 of RFC8785 canonical JSON of that filter; only ASCII enums/keys occur. Source arrays are not forwarded, and are not part of per-source filter hash; source ID is independently sealed. The v2 request sends kinds as hard pre-search filters, an explicit amendment from v1 routing-only semantics. ACL AND categories AND kinds occurs in database before retrieval/hydration. Core also validates returned kinds/category membership in requested sets and immutable descriptor vocabulary. Result postchecks do not replace prefiltering.

Unknown category accepted by no caller-visible supporting source gives generic400 INVALID_SELECTOR; hidden source vocabularies cannot change response. Visible v1-only source under v2 category restriction receives zero calls and skipped unsupported-selector (selector categories/protocol); visible supported source with disjoint vocabulary is skipped categories. Existing kinds skips remain. Unsupported versions never trigger unfiltered fallback.

Before dialing, visibility/grants/request narrowing/class/category/version evaluation determines eligible sources. Above16 eligible sources returns422 SOURCE_SELECTION_TOO_BROAD with fixed text "Narrow the authorized source selection to at most 16 sources." and auditRef only: zero dials/signings, no source count/list. Hidden sources do not count. Explicit sources input separately caps16. Re-evaluate arms before signing; a lost arm disappears without replacement fanout. Four surfaces expose identical normalized requests, fixed errors and honest skipped/degraded coverage. GUI uses "All authorized"; empty selected category is validation error, not all.

## 3. Coverage, budgets and rendering
Core retains the five-outcome consulted partition: answered, timedOut, unavailable, refusedBySource, refusedByPolicy. skipped is disjoint. Existing truncatedResults/invalidResults remain subsets of answered. V2 adds partialSources modifier [{id,reasons}] subset answered. Satellite retrieval block is required: complete with no reasons, or partial with at least one bounded reason store-unavailable/deadline/acl-stale/ingest-stale. No driver IDs, endpoints, private names/counts or raw error text cross the boundary. Hidden/unentitled driver failure cannot alter coverage.

Zero effective entitlement gives complete empty results, zero engine calls, independent of hidden store health. Nonempty entitled configured store set with zero successfully readable stores gives503. Valid partial entitled-store response remains core answered plus partialSources. Missing/malformed retrieval block => unavailable:transport. Coverage precedes groups even when presentation truncates every result. Core groups by Service and preserves source-local ranking; no global RRF/score normalization. Satellite internal ACL-first RRF remains inside one group.

Ceilings:16 sources, concurrency4, limit1..25 default8, leg500..8000ms default3000, whole min(20000,timeoutMs*ceil(N/4)); source search256KiB decompressed, aggregate1MiB; internal satellite driver fanout8/concurrency4 within remaining deadline. Excess result count is truncated; oversize envelope cancels stream and uses unavailable:transport. Limits require measured qualification, not performance claims.

All source-authored title/snippet/label/content/link bytes stay inside relay-generated random-sentinel untrusted blocks or safe text nodes. No label enters wrapper attributes. Ref stays sealed. Every count/link/explain/export obeys identical current Guardian authorization; inaccessible targets silently absent. Labels/audiences never widen through fusion.

## 4. Addresses, GET and byte windows
V2 address seal payload: {v:2,s,dv,c,r,f,fh,iat}; source, immutable descriptor, opaque compartment, raw cited-ref, normalized filter and hash are bound. Current ACL/identity always rechecked; addresses are confidential, non-expiring and not caller-bound, conveying no authority. v1 addresses decode by their own historic static rules. Category/label change never widens address: source applies sealed filter against current metadata/cited revision; core validates against pinned descriptor vocabulary. Missing immutable descriptor fails closed.

Search paging is unsupported; narrow/reissue on truncation. GET document continuation only: caller supplies handle and optionally continuation OR ifNoneMatch. V2 rejects legacy raw continueFrom/contentHash. Continuation seal {v:2,s,dv,c,r,fh,h,next} uses separate cryptographic domain; matching source/ref/pin/compartment/filter required, next>0. Current authorized other reader can reuse address/continuation; revoked reader cannot. Core derives source request offset/hash from sealed token, never caller raw offset.

Source request/response shapes are in schema. Channel first, fresh assertion when asserted, then current Guardian/ref compartment/cited revision/filter checks, THEN digest/ETag comparison. Missing/erased/unentitled/wrong-compartment/filter-excluded targets give identical refused. Authorized continuation hash mismatch gives content_changed. Source alone issues notModified; core never uses a cached digest for authorization.

Source fetch uses original CAS bytes and verifies full revision hash; engine/latest substitution prohibited. Response content_base64 is canonical RFC4648, decoded cap262144; source response cap384KiB, timeout<=8000ms. offset equals requested offset, byteLength equals decoded size, offset+size<=totalBytes; truncated requires positive size and end<totalBytes, final end=totalBytes. Empty document only offset=size=total=0,truncatedfalse. Source configured maximum document size bounds totalBytes. Core validates range metadata and syntax; full first-window content additionally gets core hash verification. Core cannot verify full-document hash from a partial window and claims no such proof.

Core wraps valid content as {protocol_version:2,status:"content",content_base64,sha256,offset,byteLength,totalBytes,truncated,continuation?,provenance:{sourceId,compartment,contentKind,category},retrieval,auditRef}. Only core seals next continuation, iff truncated. notModified includes protocol_version,status,auditRef; refusal includes these plus core enum code. Malformed source shape=>source_protocol_error with no bytes; unavailable=>source_unavailable; timeout=>source_timed_out. Binary remains binary; text previews fence decoded text and cannot claim a lossy rendering is original bytes.

## 5. Automatic lifecycle and future source permissions
Internal ensure is authenticated governed control-plane reconciliation, not arbitrary caller search input. Unique deployment+kind+stable ID and durable idempotency key ensure one opaque identity across retries/renames. Pending registry/grant stages are unreadable; transaction/reconciliation completes before active. Personal owner receives explicit read and write. Reciprocal read is two explicit independently auditable consent grants; no household default or future-user inheritance. Project grants distinguish user/group stable IDs and read/write independently; write does not imply read. Admin is not content bypass. Deactivation disables access without deleting retained notes. Unknown historical ownership stays quarantined; existing paths/MOCs/vectors unchanged.

Future forge ACL contract only: immutable forge instance+repository ID and stable user/team IDs, never names, determine source/container mappings. Permission stream has independent cursor; webhook is a hint, bounded inventory sweep is truth. Event delivery idempotent by source event ID; delete/revoke and repository visibility changes commit audited mapping version without embedding rewrites. Incomplete inventory never proves removal; failed permission refresh does not advance cursor. Finite configured acl_staleness_budget gates availability; unknown/missing/stale-required mapping excludes affected corpus. Source-mirrored internals retain genuine per-item ACL granularity. Renames preserve logical IDs; transfers/visibility changes require fresh trusted permission facts and do not inherit new audience by name. Connector manifest namespaces, ACL ceiling and scoped append credential are validated relay-side. No forge connector, ingestion or production permission mutation is activated by this contract.

## 6. Executable scope and review gate
JSON Schema is structural validation, not authorization or cryptographic proof. Supplemental semantic checks enforce partition/set relations, cross-field byte ranges, filter hash bindings and current ACL. fixtures.json and validate_contract.py run structural positives/negatives and four-surface normalization parity; they do not claim network, security, scale or runtime acceptance. Full accepted driver conformance matrix remains mandatory, including65/1000/10000 synthetic identities with constant descriptor size and no cross-owner disclosure. Independent engineering acceptance of exact artifact hashes releases dependent implementation, not production deployment.

## 7. Native HTTP transport seat
Core REST is POST /knowledge-queries with query schema. External source search is HTTP POST to that Service's owner-configured knowledge_query_endpoint with sourceSearchRequest; get is HTTP POST to owner-configured knowledge_get_endpoint (or configured query endpoint default) with sourceGetRequest. Distinct operation endpoint dispatch must be configured or unambiguously route by validated request shape; no MCP tool name or FastMCP transport is invented as the native wire. Channel authentication and assertion validation precede operation handling in shared middleware. Direct MCP, when separately exposed, adapts through the same Guardian rather than bypassing it. Caller bearer/session credentials never travel to source/store. This read contract does not activate standalone exchange/token services, ingestion or production backup expansion.

## v1.1 normalization-order clarification
Adapters first validate raw request shape, primitive types, q/individual string bounds and enum/pattern values, with raw body cap64KiB and each selector array cap256 elements. Raw arrays may contain duplicates but cannot be empty. They then deduplicate and lexically sort sources/kinds/categories, expand omitted kinds, and validate the normalized query against the published schema (sources<=16, categories<=32, kinds<=3 and uniqueItems). Thus17 distinct sources and33 distinct categories reject, while repeated copies of a valid value collapse. Limits refer to normalized distinct items unless this paragraph labels them raw. Input beyond raw caps rejects before normalization; no unbounded parsing/deduplication. This preserves source deduplication and applies it consistently to all dimensions. JSON Schema query is the normalized boundary, not raw adapter input. REST/MCP/CLI/GUI share this exact ordering; test adapters demonstrate normalization only, not live transports.
